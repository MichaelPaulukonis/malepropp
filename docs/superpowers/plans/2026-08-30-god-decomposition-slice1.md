# god() Decomposition, Slice 1 (Pronoun Lexicon) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extract `lib/propp.js`'s `god()`-internal pronoun/gender-lexicon helpers (`possessive`, `pronounobject`, `pronoun`, `reflexivePronoun`) into a standalone, directly-unit-testable module, and lock in a seeded golden-master regression fixture that all later `god()`/`nTemplates()` decomposition slices can diff against.

**Architecture:** `god()` (lib/propp.js:293-940, ~650 lines) is one function building ~26 inner closures that all share `bank`/`cache`/`settings` by closure capture (malepropp-x82). Untangling all of it in one pass is high-risk — this plan does the smallest safe slice: the four pronoun functions are the *only* cluster in `god()` with zero dependency on `bank`/`cache`/`settings` (they only need `world.gender`), so they can move to a plain factory function `createPronounHelpers(world)` with no dependency-injection wiring beyond that one parameter. The factory return values get assigned to the exact same local `var` names `god()` already uses (`possessive`, `pronounobject`, `pronoun`, `reflexivePronoun`), so **every existing call site inside `god()` (createCharacter, etc.) needs zero changes** — only the four `var x = function(...){...}` declarations themselves are replaced.

Remaining `god()` clusters (character creation, place, dialogue/`tone`/`converse`, the dead `battle()`, `list`/`or`/`select`/`dump`/`getName`) and `templates.js`'s `nTemplates()` 33-function split are **out of scope** for this plan — see "Deferred work" at the end. Per the writing-plans skill's Scope Check, those are independent subsystems and get their own plans.

**Tech Stack:** Node ES modules (`"type": "module"`), Mocha + Chai, no bundler.

### Task 3: Implement `lib/god/pronouns.js`

**Files:**
- Create: `lib/god/pronouns.js`

This is a verbatim move of `lib/propp.js:569-617`'s four function bodies, wrapped in a factory that takes `world` as an explicit parameter instead of closing over the module-level `world` object — that's what makes it importable and testable with no other `propp.js` state.

- [ ] **Step 1: Write the module**

```js
// lib/god/pronouns.js
//
// Pure gender-lexicon helpers, extracted from propp.js's god() closure
// (malepropp-x82, slice 1). No dependency on bank/cache/settings - only
// needs world.gender, passed in explicitly so this is independently
// testable and has no import cycle back into propp.js.

var createPronounHelpers = function (world) {
  var reduceToGender = function (gndr) {
    // if a character object is passed in, reduce it to its .gender
    return gndr && gndr.gender ? gndr.gender : gndr;
  };

  var possessive = function (gndr) {
    gndr = reduceToGender(gndr);
    return gndr === world.gender.male
      ? "his"
      : gndr === world.gender.female
        ? "her"
        : "its";
  };

  // third-person
  var pronounobject = function (gndr) {
    gndr = reduceToGender(gndr);
    return gndr === world.gender.male
      ? "him"
      : gndr === world.gender.female
        ? "her"
        : "them";
  };

  var pronoun = function (gndr) {
    gndr = reduceToGender(gndr);
    return gndr === world.gender.male
      ? "he"
      : gndr === world.gender.female
        ? "she"
        : "it";
  };

  // none of these deal with plurals
  var reflexivePronoun = function (gndr) {
    gndr = reduceToGender(gndr);
    return gndr === world.gender.male
      ? "himself"
      : gndr === world.gender.female
        ? "herself"
        : "itself";
  };

  return {
    possessive: possessive,
    pronounobject: pronounobject,
    pronoun: pronoun,
    reflexivePronoun: reflexivePronoun,
  };
};

export default createPronounHelpers;
```

Note: the `reduceToGender` helper is a new (tiny) shared extraction of the `gndr && gndr.gender ? gndr.gender : gndr` line that was duplicated identically in all four original functions — this is a pure DRY cleanup of code that's moving anyway, not a behavior change. Confirm this in Task 2's tests (already covers it via the `{ gender: "male" }` case).
